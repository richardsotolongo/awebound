# AGENTS.md — apps/web

The whole site: Next.js 16 App Router. Server Components read the catalog directly from server code; Client Components handle interaction and call Server Actions. Brand rules live in `packages/brand/AGENTS.md` and the `awebound-brand` skill: read them before visual work.

## Layout

```
src/
├─ app/                    routes (pages, route handlers, sitemap, robots, llms.txt, icons)
│  ├─ page.tsx             home: the tagline on the lead piece's plate, that piece up close, the founder's note, the release as a wall, release sign-up
│  ├─ shop/                (list)/ the listing (collection selector + category tabs) with its loading state; [slug]/ product pages, cached for a minute
│  ├─ collections/         every release by name; /collections/<slug> opens the shop filtered to it
│  ├─ about, contact, faq, refunds, privacy, terms, bag, sign-in, account
│  └─ auth/                callback (OAuth/PKCE), confirm (email token hash), sign-out (POST)
├─ features/               one folder per feature (UI)
│  ├─ home/                Campaign (the opening plate), LeadPiece (the brand paragraph, status, close-up, name, price, Scripture), Founder (Richard's note)
│  ├─ release/             ReleaseCard (the brand ProductCard fed from a ProductSummary), ReleaseWall (tiles with no gaps), releaseStatusText
│  ├─ catalog/             CatalogView (collection/category selectors), ShopHeader, URL state, toolbar, filters, chips, grid, query helpers
│  ├─ product/             gallery (the stage), purchase (type and price, color/size, Save to bag or Add to bag, the phone buy bar), StoryBand, PieceNav, delivery and returns summary, size guide
│  ├─ bag/                 zustand store (persisted), drawer, bag page, checkout + notify form
│  ├─ contact/ auth/ account/ legal/
├─ server/                 server-only code (never import it from a Client Component, except actions.ts)
│  ├─ actions.ts           Server Actions: validateBag, startCheckout, loadMoreProducts, sendContact, subscribe, updateProfile, deleteAccount
│  ├─ catalog.ts           getCatalog (Fourthwall + brand content), searchProducts, getFacets, getProduct, withFallback
│  ├─ catalog-merge.ts     merges Fourthwall products with the brand content by slug; previews for the rest
│  ├─ catalog-search.ts    search, filters, facets and sorting over the merged catalog
│  ├─ fourthwall.ts        Storefront API client (product list cached 60 s, cart creation)
│  ├─ bag.ts               re-pricing the bag, creating the checkout
│  ├─ messages.ts          contact messages and drop-note sign-ups (Supabase + email)
│  ├─ email.ts, email-templates.ts   Resend, or the terminal in development
│  ├─ errors.ts            UserError, Result, run(), parse()
│  ├─ env.ts               server-only env (zod)
│  ├─ scripture.ts         resolves Scripture records to the site's translation (SCRIPTURE_TRANSLATION), site verses, the notice
│  └─ content/             catalog.json (per product: code, release, position, plate, Scripture record, design story, preview price and per-size prices, size guide, images; plus `sizeGuides` per blank), verses.json
├─ shared/                 zod schemas, types and helpers used by both server and browser
├─ components/             site chrome: header, footer, Sheet (native <dialog>), PageHeader, FitName (a release name sized to fill its line), icons,
│                          JsonLd (structured data), AskAi (the footer's assistant links)
├─ lib/                    public env (zod), Supabase clients (browser, server, admin), site config and
│                          pageMeta, usePath, delivery.ts (confirmed fulfillment facts; null until confirmed)
├─ styles/                 site.css, sheet.css, shop.css, product.css, home.css, prose.css (all @layer components)
└─ proxy.ts                Next 16 proxy (formerly middleware): refreshes Supabase session, guards /account
```

## Conventions

- **Data**: Server Components call `server/catalog.ts` directly, wrapped in `withFallback` so a Fourthwall outage renders an empty state instead of crashing. Fourthwall's product list is fetched with `next: { revalidate: 60 }`, so the home page, Collections, About and the sitemap stay static and refresh every minute. Product pages are cached the same way but render on their first visit (`revalidate` plus an empty `generateStaticParams`), so a deploy never depends on Fourthwall. Don't add `no-store` on the catalog path.
- **Server Actions** (`server/actions.ts`) are the only way the browser reaches the server. Each one parses its input with a schema from `shared/`, reads the user from the Supabase session, and returns `Result<T>`: `{ ok: true, data }` or `{ ok: false, error, fields? }`. Next hides thrown messages in production, so never rely on a thrown error reaching the client; throw `UserError` for messages the shopper should see.
- **Secrets** stay in `server/` and `lib/supabase/admin.ts` (`import "server-only"`). Brand content is server-only too, so the catalog JSON never ships to the browser.
- **Shop state lives in the URL** (`collection`, `category`, `q`, `color`, `size`, `minPrice`, `maxPrice`, `sort`). Collection and category are links (`shopHref`), so they push history: no `collection` means Latest Drop (the newest release, from `CatalogIndex.releases()`), `all` means every collection. The sheet's filters use `useCatalogState()`, which updates optimistically and replaces the URL in a transition.
- **Scripture**: never hard-code a verse in a component. Products carry `scripture` (a `ScriptureQuote` resolved on the server); site verses come from `VERSES` in `server/scripture.ts`. Render with the brand `ScriptureQuote` / `ScriptureRef`, which add the quotation marks and the "— NIV, excerpt" label.
- **Release status and availability are two things.** A release's `status` is `preview` while none of its pieces is in Fourthwall, `partial` once some are, and `open` when all are; every piece carries it as `releaseStatus`. A piece has its own `availability`: `preview`, `available`, `partial` (some sizes sold out) or `sold_out`. Release-level wording (the home status sentence and sign-up, the shop header, Collections, sign-in, `llms.txt`) follows the release and handles all three values by name, never as “not open”; `releaseStatusText` gives the standard sentence. A card, the home page's piece and the product page speak for the piece (`pieceStatus`, `priceLabel` in `features/catalog/query.ts`): “Sold out”, “Some sizes sold out”, “Not open for ordering yet” (only inside a `partial` release), and “From $40” when sizes differ in price. Nothing may say ordering isn't open beside a piece that can be ordered.
- **Internal codes**: `code` stays in data (SKUs, records) but is never rendered, searched or put in metadata. Structured data and `llms.txt` carry no SKU for the same reason.
- **Metadata**: an indexable page exports `pageMeta({ path, title, description })` from `lib/site.ts`, which sets the canonical address and the whole share card (a page's `openGraph` replaces the layout's). Shop views build their address with `shopCanonical`, which the sitemap shares. Structured data goes through `<JsonLd>`. Only confirmed facts: no offer for a preview, no shipping or return details until they are confirmed, Scripture by reference only in `llms.txt`.
- **Current path**: use `usePath()` (`lib/pathname.ts`), never `usePathname()` directly, for anything rendered on the server. Vercel renders the prerendered home page as `/index`; the raw value once made the footer and header differ from the browser's render (a hydration error in production only).
- **Bag**: `useBag` (zustand, persisted to localStorage, rehydrated after mount). The `validateBag` action re-prices it whenever it's shown; never trust client prices. `startCheckout` answers `{ url }` and the browser goes to Fourthwall's hosted checkout. Checkout takes the lines that can be ordered now; saved previews stay in the bag, marked, and outside the subtotal (a bag holding only saved previews shows what they come to instead, with a notice in place of the button). A piece's SKUs change when it goes from preview to on sale (they become Fourthwall's variant ids), so each line is sent with its piece, color and size (`toLineInput`) and `CatalogIndex.findVariants` finds it again: a saved selection survives publishing. A line that matches nothing is removed with a notice.
- **Auth**: Supabase via `@supabase/ssr`. Passwordless only (Google OAuth, email link or 6-digit code). Everything degrades to "Accounts open soon" when `NEXT_PUBLIC_SUPABASE_*` is unset.
- **Styling**: brand classes (`.aw-*`) for type and components, Tailwind utilities for layout, tokens for every color. No raw hex. Garment swatches go through `colorCss(color)` from `@/shared`: the brand token when the color is known, otherwise Fourthwall's swatch hex (product data, not styling). Fonts are self-hosted from `@fontsource-variable/*` via `next/font/local` (no Google Fonts requests).
- **Motion**: Motion is one idea: the garment image travels between a tile and its product page (view transitions), and pages cross-fade. Nothing animates on load or on scroll. Artwork, Scripture and buttons are whole and readable in every frame: never cropped, wiped or faded in. Reduced motion gets instant navigation. The morph is React's `<ViewTransition name={"piece-" + slug}>` around a tile's listing image and the product stage's first frame: both ends show the same picture (`1.webp`), and a name appears once per page (the home hero shows a different picture, so it is unnamed; a product page's wall leaves out its own piece). Neighbour links pass `transitionTypes`. Product pages are cached (`revalidate` plus an empty `generateStaticParams`) so the destination is ready. Anchors land below the header (`scroll-margin-top` on every `[id]`).
- **No labels above headings** on any page (no `.aw-label` over an `h1`–`h3`, no “Latest drop · Release 01” strings, no status chips). Context goes in the heading or a plain sentence. Product cards put the name first for the same reason. Form labels (Color, Size, Collection) stay.
- **Plates**: a piece's `plate` (`{ token, ink }` in `catalog.json`) names its `--plate-*` token and the ink (bone or coal) its lettering takes. `.aw-plate` (brand package) sets the field; only large lettering, filled buttons and images go inside it. A piece without a plate falls back to its listing image on coal.
- **React 19 lint rules**: don't call setState synchronously in effects. Adjust state during render when a prop changes (see `product-grid.tsx`, `site-header.tsx`).
- **The product stage** (`features/product/product-gallery.tsx`): on desktop the images fill the left of the page from the header down and stay put while the buy column scrolls; the column is never wider than 1.05 times its height, so a 4:5 image that covers it loses only background and always shows the whole garment. Thumbnails sit in a strip under it, never over the garment. Hovering with a mouse zooms the image 2× around the pointer; on touch, pressing and holding for 180 ms zooms and dragging looks around, while a quick swipe still changes images. Lifting the finger or leaving the image zooms back out. Tiles and cards don't zoom.
- **Images**: product images are plain `<img>`. `public/products/<slug>/` holds the site's product images, made by `assets/mockups/fourthwall.py` and `compose.py` from each product's image list in Fourthwall, in the same order: `1.webp` (the listing image), `2.webp` (hover), and so on; four for tees and hoodies, six for caps. Finished photos are cropped to 4:5 and Fourthwall's cut-out renders are placed on the piece's own surface. A product not in `assets/mockups/fourthwall.json` falls back to its mockup (`front`/`back`/`side.webp`). Beside them, built from the slug and never listed in `images` in `catalog.json`: `detail.webp`, a close-up of the piece's artwork cropped from its Fourthwall render (640×800, the whole print, never enlarged), shown on the home page and in the product page's design story; and the plate: `plate-wide.webp` and `plate-tall.webp` (the surface alone, lit where the garment sits) and `piece.webp` (the listing view cut out with its shadow). Every piece needs all four. These images are used for previews and live products alike; Fourthwall's own photos are only a fallback (`catalog-merge.ts`). The founder portrait is `public/about/richard-{480,960}.webp`; its captions and alt text name Richard and nothing he is wearing, and it is never presented as a photo of a product.
- **A new release**: add a collection (slug, name, number, tagline, story, scriptureRef) and its products to `catalog.json`, each with a Scripture record (exact NIV and KJV text), a design story (theme, call, art, meaning) and a `plate` (`{ token, ink }`). Add each piece's surface to `STYLE` in `assets/mockups/compose.py` and its `--plate-*` token to `packages/brand/src/styles/tokens.css`, run `compose.py` for the images, close-up and plate (check the crop in `VIEWS`), and take each `ink` from the contrast table it prints. Latest Drop, the home page, Collections and the shop selector pick it up. The home page opens on the release's first `featured: true` piece in release order (or its first piece). A release name with a character missing from `WIDTHS` in `components/fit-name.tsx` sets a little short; add the character's width.
- **Size guides**: `sizeGuides` in `catalog.json` holds each blank's measurements exactly as the owner's guide image prints them (fractions as text, one value per `measures` column), its fit line, an optional sizing note (shown in the guide and under the size buttons; none today) and the image (`public/size-guides/*.webp`, made at 1600 px wide from the PNGs in `assets/size-guides/`; the Organic Oversized PNG has the owner's “US sizing note” box cut out). A product's `sizeGuide` picks its guide, and the guide's sizes are the sizes a preview offers. `blank` (supplier and Fourthwall id) never leaves the server. The sheet widens to 560 px for the image; the measurements also render as a table for screen readers. A guide without an image shows the table.
- **Returns copy** mirrors Fourthwall's return policy and lives in four places that must agree: `app/refunds/page.tsx` (the full policy), the FAQ's Returns and refunds answers, `features/product/delivery-summary.tsx` and `app/llms.txt/route.ts`. The reporting window is `DELIVERY.problemWindowDays`.
- **Previews**: a content entry with no Fourthwall product is listed with `preview: true` (content price and `sizePriceCents`, the size guide's sizes and the site's images; SKUs like `A3-B01-FADED-BLACK-M`). The product page says ordering isn't open and offers "Save to bag"; a bag holding only previews explains that it saves selections and shows a notify form instead of checkout; `startCheckout` leaves preview lines out and refuses a bag with nothing else in it.

## Commands

```bash
pnpm --filter @awebound/web dev        # http://localhost:3000
pnpm --filter @awebound/web typecheck  # next typegen + tsc
pnpm --filter @awebound/web lint
pnpm --filter @awebound/web build
```

No tests (owner's instruction). Verify by building and walking the flows in a browser on desktop and a phone width, with and without reduced motion: the home page's two buttons, the lead piece and the wall → collection + category selectors (e.g. Behold + Hats, an empty combination) → product (a tile's image should travel into the stage; the next and previous pieces slide in) → Save to bag / Add to bag, from the button and from the phone bar → checkout (lands on Fourthwall once live); notify; contact; sign-in. Check that lettering fits at 320px and that nothing but lettering, buttons and images sits on a plate. Check error messages with `pnpm build && pnpm start` too: `next dev` shows thrown messages that production hides.
